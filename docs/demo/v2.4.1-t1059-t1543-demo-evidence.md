## Detection 2: T1543.002 Systemd Service

### Test scenario

Attacker creates a malicious systemd service unit file under `/etc/systemd/system/` using bash. The YAML detection engine identifies the file creation via auditd PATH records and the creating process name.

### Command used

```bash
# Run as root (or with sudo) on the monitored endpoint
sudo bash demo/threatactor_setup.sh
```

Or manually:

```bash
sudo bash -c 'echo "[Unit]
Description=Backdoor Service

[Service]
ExecStart=/tmp/backdoor.sh

[Install]
WantedBy=multi-user.target" > /etc/systemd/system/threatactor-backdoor.service'
```

### Expected result

- auditd emits SYSCALL + PATH records for the file write
- Audit event aggregator groups them into a single normalized event
- T1543.002 YAML rule matches on `file.path` and `process.name`
- Alert created with `detection_engine = YAML`, MITRE technique T1543.002
- Investigation page shows Evidence Summary with file.path and process fields
- SOAR playbook `t1543_systemd_persistence_review` auto-runs and creates a case note

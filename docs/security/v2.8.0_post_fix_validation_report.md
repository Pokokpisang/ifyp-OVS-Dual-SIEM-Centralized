## 2. Executive Summary

All four **High severity** findings and five of six **Medium severity** findings from the baseline report have been closed. Server-side session invalidation now works correctly: after logout, replaying the old signed cookie returns HTTP 302 rather than 200. CSRF protection rejects mismatched `Origin` headers on all state-changing endpoints. Role-based access control correctly separates admin and client accounts — client-role users receive HTTP 403 on admin-only endpoints while retaining read-only access. All five OWASP security headers are now present on every response. The API metrics endpoint now requires a valid `X-Agent-Key`. SOAR audit identity is read exclusively from the server-side session, not from the request body. The API container runs as `appuser` (UID 1001), not root.

Three findings remain open:
- **ST-026 (Low):** Pydantic version URL leaks in validation errors — low exploitability, deferred
- **ST-031 (Low):** Server IP in `/install.sh` — by design for LAN deployment
- **ST-038 (Medium):** Gemini API key in `.env` — requires secrets manager infrastructure (v2.9.0 task)

### ST-010 — Session Replay After Logout

```
# Before logout
curl -c /tmp/jar.txt -X POST http://localhost:8000/login -d "username=admin&password=admin"
curl -b /tmp/jar.txt http://localhost:8000/dashboard
→ HTTP 200 ✓ (session valid)

# Logout (server deletes server_sessions row)
curl -b /tmp/jar.txt -X POST http://localhost:8000/logout

# Replay same signed cookie
curl -b /tmp/jar.txt http://localhost:8000/dashboard
→ HTTP 302 (redirect to /login) ✓

v2.7.0 result: HTTP 200 (FAIL)
v2.8.0 result: HTTP 302 (PASS)
```

## 5. Risk Acceptance — Residual Findings

### ST-026 — Pydantic Version Disclosure (Low)

**Risk:** Pydantic version URL (`https://errors.pydantic.dev/2.5/v/...`) visible in validation error responses. Discloses exact Pydantic version.

**Acceptance rationale:** Low exploitability — version alone does not enable attacks. Requires a secondary known vulnerability in Pydantic 2.5 to be useful to an attacker. No such known RCE or privilege escalation CVE exists. Deferred to v2.9.0.

### ST-031 — Internal IP in `/install.sh` (Low)

**Risk:** `GET /install.sh` returns a script with a hardcoded internal server IP (`192.168.88.146`).

**Acceptance rationale:** By design for LAN agent deployment. The endpoint is intentionally public for agent installation. IP is a local RFC 1918 address with no external routing. Acceptable for local/demo use.

### ST-038 — Gemini API Key in Plaintext `.env` (Medium)

**Risk:** `GEMINI_API_KEY` stored as plaintext in `api/.env`. Exposed in: leaked env file, container image layer inspection, or `/proc/*/environ` access.

**Acceptance rationale:** Requires local file access or container escape, both of which are higher-severity preconditions. Key is for the Gemini AI triage feature which is disabled by default (`AI_TRIAGE_ENABLED=false`). Mitigation path for v2.9.0: Docker secrets or a secrets manager (HashiCorp Vault / AWS Secrets Manager). **Key should be rotated before any production deployment.**
